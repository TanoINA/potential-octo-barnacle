# Release and recovery

Product semver is exactly **0.3.0** in npm, Cargo and Tauri; build identity is separate (UTC timestamp with fractional seconds, git SHA and clean/dirty/unknown). `build.rs` emits only allowlisted public compile-time values and does not mutate the process environment. Cargo reruns on application source, config and git index/HEAD changes; cached identical builds deliberately retain their build identity.

## Current availability
No genuine publisher certificate, updater private key, hosting endpoint or signed public release was supplied. Automatic updates are **not configured** in a normal build. About reports installer signing as **Unknown (not verified at runtime)**; an Ed25519 update key is not evidence of Authenticode signing. No certificate or trusted identity is generated by these scripts.

## Automatic updates (operator provisioning required)
Embed `AETHER_UPDATE_ENDPOINT` and `AETHER_UPDATE_PUBLIC_KEY` when building. The key is the base64-encoded minisign Ed25519 public-key file used by Tauri, not an arbitrary raw string. Only public DNS HTTPS URLs without userinfo, query credentials or fragments are accepted (including artifact/redirect URLs); literal IPs and local hostnames are rejected. Private DNS overrides still require an operationally trusted network/DNS configuration. No webview IPC can supply an endpoint or key, and updater plugin JS permissions are not granted.

The native check stores the checked release, requires its semver precedence to exceed the running version (build metadata alone does not qualify), validates its download URL and disables insecure TLS/HTTP. Installation requires explicit confirmation and the exact checked version. Official updater verification checks Ed25519 and requires the signature's authenticated version to match the advertised release, blocking inflated-version replay of older artifacts. Current official Tauri CLI signatures with version trusted-comments are required. Checking does not download or execute anything. Network/verification failure is an error, never success.

## Signed build
Use `scripts/build-signed-release.ps1` only with a genuine CurrentUser code-signing certificate and private key, `AETHER_CERTIFICATE_THUMBPRINT`, HTTPS `AETHER_TIMESTAMP_URL`, `TAURI_SIGNING_PRIVATE_KEY` (and password if needed), and the two public updater variables. Keep private keys in protected CI secrets; never command-line arguments, source files, release records or logs. This script enables `createUpdaterArtifacts` only in its build override; ordinary local builds do not require signing secrets. It fails closed on missing credentials, build errors, missing signatures, unsigned/wrong-publisher installers or missing signed-version binding. It archives verified installers, signatures and SHA-256 records; it does **not** upload or claim a published endpoint. Review CI log masking before using private-key environments.

## Offline install / rollback
1. Obtain an explicit local EXE/MSI from a trusted distribution channel. Independently obtain its SHA-256 and publisher certificate thumbprint; a hash from an untrusted adjacent file is not publisher authentication.
2. Run `scripts/verify-installer.ps1 -Installer <explicit-local-path> -ExpectedSHA256 <64-hex> -TrustedPublisherThumbprint <40-hex>` on Windows. It requires matching SHA-256 **and** valid Windows Authenticode chain **and** the pinned certificate. Missing, unsigned, wrong publisher or mismatch fails closed. The verifier never launches the installer. Reverify immediately before manually launching; don't permit other processes to replace the file between verification and use.
3. Save work, close AetherAgent, back up the relevant `.aether-agent` profile and workspace data, then explicitly run the verified installer through Windows. No tool silently starts an arbitrary URL or bypasses Windows prompts.
4. For rollback, retain a **previous** signed installer and its release record outside `target`, and pass `-PreviousReleaseRecord <record.json>` to the signed build script. The new record links that retained record only after re-verifying its files. With no supplied previous record the field is null: there is no fabricated rollback artifact. Keep the prior archive immutable and reachable; certificate rotation requires separately validating historical publisher pins.
5. To recover, select that prior installer and run the same verifier against its independently trusted old hash/publisher; explicitly confirm the manual downgrade in Windows. Restore a compatible backup if history/schema migration is not backward compatible. This foundation provides retention and verification, not an automatic schema rollback or proof of backward compatibility. Test recovery in an isolated profile before publication.
