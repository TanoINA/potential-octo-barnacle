# Release and recovery

Product version is **0.3.0** across npm, Cargo, and Tauri. Build identity is tracked separately: a UTC timestamp with fractional seconds, git SHA, and a clean or dirty status flag. `build.rs` emits only allowlisted compile-time constants and never touches the process environment. Cargo reruns when source, configuration, or git HEAD changes. Cached identical builds keep their original build identity.

## Current status

Normal local builds do not configure automatic updates. They do not include a publisher certificate, updater private key, or hosted endpoint. The About dialog reports installer signing as **Unknown (not verified at runtime)**. An Ed25519 updater key only verifies update archives; it is not proof of Windows Authenticode signing.

## Automatic updates

To enable update checks in a build, set two variables at compile time:
- `AETHER_UPDATE_ENDPOINT`: HTTPS URL to your update manifest (e.g. `https://updates.example.com/latest.json`).
- `AETHER_UPDATE_PUBLIC_KEY`: base64-encoded minisign Ed25519 public key generated by Tauri.

The updater enforces several checks before touching anything:
- Endpoints must be public HTTPS URLs. IP addresses, local hostnames, query strings, and fragments are rejected.
- Webview code cannot supply endpoints or replace the signing key.
- The remote version must be strictly newer than the running version according to semver. Metadata changes alone are ignored.
- The downloaded signature must match both the binary and the advertised version comment to prevent downgrade attacks.
- Checking for an update only downloads metadata. It never executes code or downloads the installer payload automatically.

## Building signed releases

Use `scripts/build-signed-release.ps1` when producing a signed release on Windows. It requires:
- A code-signing certificate installed in the `CurrentUser` store.
- `AETHER_CERTIFICATE_THUMBPRINT`: SHA-1 thumbprint of the certificate.
- `AETHER_TIMESTAMP_URL`: RFC 3161 timestamping service URL.
- `TAURI_SIGNING_PRIVATE_KEY`: private minisign key (and password if set).
- `AETHER_UPDATE_ENDPOINT` and `AETHER_UPDATE_PUBLIC_KEY`.

Store private keys in protected CI secrets or an HSM. Never pass them as command-line flags, check them into git, or write them to build logs.

The build script turns on updater artifact generation through a build override. It verifies installers, signatures, and SHA-256 hashes, then stops with an error if anything is unsigned or missing. Verified artifacts are archived locally; the script does not upload them to a hosting server.

## Offline installation and rollback

1. Download the installer (EXE or MSI) from your distribution source. Get its expected SHA-256 hash and publisher certificate thumbprint through an independent channel.
2. Verify the installer on Windows before running it:
   ```powershell
   scripts/verify-installer.ps1 -Installer <path-to-installer> -ExpectedSHA256 <64-hex> -TrustedPublisherThumbprint <40-hex>
   ```
   The script checks the SHA-256 hash, validates the Authenticode signature chain, and confirms the pinned certificate thumbprint. If any check fails, it stops without launching the file.
3. Close AetherAgent, back up your `.aether-agent` profile directory, and run the verified installer manually.
4. For rollbacks, keep previous signed installers and their `release-record.json` outside the `target/` directory. Pass `-PreviousReleaseRecord <record.json>` when running the signed build script so new releases link back to verified rollback artifacts.
5. To downgrade, verify the older installer using its original thumbprint and hash, then run it manually. If the database schema changed between versions, restore your profile backup before launching the older version.

## Verification checks

Run the automated release policy checks:

```powershell
# Verify signature and manifest policies
cargo test --manifest-path scripts/release-policy-tests/Cargo.toml --locked

# Verify frontend update and about modal logic
npm test -- src/components/AboutModal.test.tsx src/components/release-wiring.test.ts src/components/SettingsModal.test.tsx

# Verify installer verification logic against unsigned and tampered fixtures
powershell -File scripts/test-release.ps1
```

These fixture tests verify error handling and signature parsing. End-to-end upgrade and rollback tests with genuine signing keys must still be run by the release operator on test machines.
